# 使用说明

安装方法见 [仓库首页](../README.md)。安装后，在能够生成图片和运行本地脚本的 Codex 环境中，上传照片并说“做微信表情包”即可开始。

## 第一次使用

1. 上传你希望制作成表情的人物照片。建议包含一张清晰脸照，再加几张能看见服装、手势或有趣道具的生活照；不必先整理成专业素材。
2. 发送下面这句话：

   ```text
   做微信表情包。
   ```

3. Codex 会先简短说明：可做软萌、写实／偏写实、漫画、3D、黏土等方向，也可以先看画风小样。你若已有偏好，就按指定风格直接制作；想先选，就使用下面的小样请求。
4. 直接制作时，Codex 会从照片中整理人物特征和可用的梗，制作角色基准、动态表情、配套美术素材，并检查后打包。
5. 下载最终 ZIP，解压后先打开 `gallery.html` 查看动画，再挑喜欢的 GIF 保存使用。

如果没有自动调用，可以明确写：

```text
使用 $create-wechat-stickers，把我上传的照片做成微信表情包。
```

只有照片、没有制作表情的上下文时，技能不会把普通图片上传直接当成制作请求。在已经开始的表情制作对话里，可以继续补充照片。

## 先看几种画风的自己

可以先试稿，再决定做哪一套。你不需要知道专业风格名称，说“更萌一点”“更像真人”“夸张得像个梗图”就能表达方向，也可以上传喜欢的画风参考。

```text
先用我的照片做 4 种画风小样：软萌 Q 版、毛绒玩偶、黑白暴漫、复古像素。
都用“我来了”这句台词，每种给一张透明动态 GIF，编号展示。
等我选好画风，再做整套。
```

如果只想先看静态画法，可以说“先做静态小样”；想连动作一起比较，就明确说“动态 GIF 小样”。未指定种数时会先选 3–6 种差异明显的方向。小样阶段只做试稿和对照，不会自动扩展成 30 张或制作投稿配图。

选好后继续用普通对话修改：

```text
选第 2 种，保留我的眼镜，头发蓬松一点；动作比小样更夸张。
按这个画风做 12 张，一半常用回复，一半用我的旅行照片选梗。
```

也可以提出“第 2 种的脸＋第 4 种的配色”，先看一张融合小样再继续。画风、比例和材质会随选择调整，人物辨识点保持一致。已经明确要某种风格或直接制作时，无需重新挑选。

看实际效果：[同一个我，12 种画风，都能动](../README.md#同一个我12-种画风都能动)。

## 不补充要求时，会做什么

未指定画风且希望直接开做时，默认制作活泼的大头 Q 版，保留照片中可辨认的脸型、眼镜、发型、胡须等特征。参考图提供的是画风，你自己的照片决定主角是谁。

默认数量为 30 张，分成两套各 15 张：约一半是常用聊天反应，另一半根据照片里的服装、动作和道具设计个人梗。照片没有提供的经历不会被当成事实写进表情；材料较少时，会增加常用反应。

每个表情通常有 8 个实际绘制的动作姿态，简单动作可以用 6 个，再安排停顿和节奏导出 GIF。主图为 240×240 透明动态 GIF，并附 480px 预览和透明 PNG。完整规则见 [技能正文](../skills/create-wechat-stickers/SKILL.md)。

## 可以直接复制的请求

以下是使用示例，不是案例聊天的逐字记录。你可以只挑需要的一句，不必把每项参数都写出来。

| 想做什么 | 可以这样说 |
|---|---|
| 直接开始 | 做微信表情包。 |
| 先挑画风 | 先用我的照片做 4 种不同画风的动态小样，编号给我挑，选定后再扩展。 |
| 不知道风格名字 | 我想要萌一点，但还能看出是我；请推荐几种差异明显的画法并做小样。 |
| 先做少量 | 用这些照片做 8 张微信表情，日常聊天用，活泼一点。 |
| 指定常用台词 | 做 12 张，包含“收到”“来了”“我再睡会儿”“马上开工”。其他的你来选。 |
| 换一种画风 | 用清线漫画风做，或者做成圆润潮玩 3D／手作黏土，别太写实。 |
| 只要静态梗图 | 先做 3 张静态梗图，突出表情和笑点，这次不用动画。 |
| 个人经历变嘴替 | 用古装照做“臣附议”，用剪片场景做“正在导出别催”，其余根据我的照片选。 |
| 强调本人特征 | 保留我的眼镜、发型和胡须，不要变成没有辨识度的通用卡通脸。 |
| 使用照片梗 | 把我抱着玩偶和穿古装的照片做成几个梗，再加常用聊天表情。 |
| 只修改一张 | 第 3 张动作再明显一点，保留人物和台词，重新导出并更新完整包。 |
| 修正动画问题 | 第 5 张抬手时手指被切掉了，请重绘这一张的动作，检查后更新包。 |
| 只要单张 | 只做一张“我先躺会儿”，透明动态 GIF。 |

可以先看首页的[多画风动图与个人梗](../README.md#同一个我12-种画风都能动)：首页已展示 12 种实际 GIF，包括软萌 Q 版、毛绒玩偶、日系动漫、黑白暴漫、复古像素、剪纸拼贴、水彩绘本、国风水墨等。可按编号选择，也可以提出新方向。图中的作者角色只作效果展示；你的照片才是你这套表情的人物依据。

明确数量、风格和范围会覆盖默认方案。少于 8 张也可以做成个人散图包，但不能据此声称它已经满足完整专辑投稿数量要求。

## 下载后，各文件有什么用

以下是当前打包脚本的默认目录。项目也可能额外保留高分辨率原画或其他制作资料。

| 文件或目录 | 用途 |
|---|---|
| `complete-delivery.zip` | 完成检查后的整套交付文件，先解压再查看和取用 |
| `gallery.html` | 本地动态预览，可筛选表情并切换浅色、深色背景 |
| `overview.png` | 全部表情的静态总览，方便挑选 |
| `preview.gif` | 少量代表表情的合成预览，不能代替逐张 GIF |
| `stickers/main240/` | 240×240 独立透明 GIF，聊天使用时优先取这里的文件 |
| `stickers/large480/` | 480px 放大 GIF，便于展示和检查细节 |
| `stickers/static240/` | 透明 PNG 静帧，本身不会播放动画 |
| `albums/` | 各专辑按编号整理的主图、封面、横幅、聊天图标、角色头像等 |
| `artist/` | 作者头像和艺术家主页横幅 |
| 包内说明、清单与检查记录 | 对照每张表情的编号、文案、尺寸及检查状态 |
| 包内提示词记录 | 了解如何生成，便于之后修改同一套作品 |

`review-delivery.zip` 是检查阶段的预览包，不能当成已经完成的最终包。原始人物照片默认不放进交付 ZIP。

## 保存到微信里自己用

技能交付的是普通 GIF 和配套素材。ZIP 是文件容器，不是微信的一键安装专辑文件。

下面是按当前客户端界面操作的通用方法；iOS、Android、电脑版微信的入口和支持范围可能不同，这份仓库没有替你验证具体设备的界面：

1. 解压成品包，从 `stickers/main240/` 选一张 `.gif`，先确认在浏览器或动态预览页中会动。
2. 将原始 GIF 文件传到手机并保存。用文件传输、系统分享等方式保留原文件；不要用截图代替 GIF。
3. 在微信聊天的表情面板或表情管理页，寻找自定义表情、添加单个表情或 `+` 入口。如果当前版本允许从相册或文件选择 GIF，就选刚保存的那一张。
4. 在自己的测试会话中发送一次，检查动画和透明边缘。若收到的内容已经是可保存的表情，长按后出现“添加到表情”等选项时，也可以使用该选项。

入口不存在、GIF 不能被选择或发送后不动时，先确认选到的确实是 `.gif`，而不是静帧 PNG 或总览截图，再查看当前微信客户端的帮助与提示。这里不承诺所有客户端都支持同一路径或整套批量导入。

## 想在微信表情商店发布

自己保存单张表情和向 [微信表情开放平台](https://sticker.weixin.qq.com/) 投稿，是两个不同的步骤。

完整包会准备专辑横幅、封面、聊天图标、头像与专辑文案等素材；是否投稿由你决定。技能默认不会登录、提交或公开发布，也不会把“素材检查通过”写成“微信审核通过”。

制作及投稿时应核对 [官方制作指南](https://sticker.weixin.qq.com/cgi-bin/mmemoticon-bin/readtemplate?t=guide/index)。仓库附有 [带核验日期的规格参考](../skills/create-wechat-stickers/references/wechat-platform.md)，其中区分了官方必需项与额外交付项。例如 120px 缩略图属于兼容导出，不冒充当前已核实的强制要求。

## 常见问题

**为什么预览有白底或深色底？**

预览页面用底色帮助检查边缘。独立 GIF 的透明背景应通过文件本身检查；看到浏览器显示白色，不等于图片没有透明通道。GIF 只支持透明或不透明两种状态，半透明细腻边缘保存在 PNG 原画里。

**为什么做一套要生成很多图片？**

人物基准、每张表情的动作原画、横幅和头像都需要制作。技能没有附送图像生成额度；实际可用能力与耗用由你使用的环境决定。

**换电脑后还能用吗？**

需要有可用的图像生成工具、Node.js、本地图片处理依赖和中文字体。普通用户可以让 Codex 按 [编码说明](../skills/create-wechat-stickers/references/encoding.md) 检查环境；手动运行脚本和打包流程见 [打包说明](../skills/create-wechat-stickers/references/packaging.md)。

**只想换一句台词，需要重做整套吗？**

直接指出编号和新台词即可。文字、动作或原画变更后，要重新导出受影响的文件并复查，再更新交付包；旧检查记录不能代替新成品检查。
